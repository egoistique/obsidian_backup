# виртуальные методы, override, new, abstract, sealed, полиморфизм

## 🧠 Что такое виртуальные методы

**Виртуальный метод** (`virtual`) — это метод, который можно **переопределить в наследниках** через `override`.  
Он определяет _поведение по умолчанию_, которое может быть изменено в дочерних классах.

---

### 🔹 Пример

`class Base {     public virtual void SayHello()     {         Console.WriteLine("Hello from Base");     } }  class Derived : Base {     public override void SayHello()     {         Console.WriteLine("Hello from Derived");     } }`

`Base b = new Derived(); b.SayHello(); // "Hello from Derived"`

> 📌 Здесь работает **полиморфизм во время выполнения (runtime polymorphism)**:  
> вызов метода зависит **от реального типа объекта**, а не от типа ссылки.

---

## ⚙️ Механизм под капотом

- Компилятор создаёт для каждого класса **vtable** (виртуальную таблицу методов).
    
- При вызове виртуального метода CLR смотрит в таблицу, какой метод соответствует текущему типу объекта.
    
- Это **динамическое связывание (late binding)**.
    

---

## 🚀 Модификаторы, связанные с виртуальными методами

|Ключевое слово|Где используется|Что делает|
|---|---|---|
|`virtual`|В базовом классе|Позволяет переопределять метод|
|`override`|В наследнике|Переопределяет виртуальный метод|
|`abstract`|В абстрактном классе|Обязывает наследников реализовать метод|
|`sealed`|На классе или методе|Запрещает дальнейшее наследование / переопределение|
|`new`|В наследнике|Скрывает (не переопределяет) метод базового класса|

---

### 🔹 Разница между `override` и `new`

`class Base {     public virtual void Show() => Console.WriteLine("Base"); }  class Derived : Base {     public new void Show() => Console.WriteLine("Derived"); }`

`Base b = new Derived(); b.Show(); // Base Derived d = new Derived(); d.Show(); // Derived`

> 📌 `new` — это **скрытие (method hiding)**, а не переопределение.  
> Вызов зависит от **типа ссылки**, а не объекта.

---

### 🔹 Разница между `virtual` и `abstract`

|Признак|`virtual`|`abstract`|
|---|---|---|
|Реализация в базовом классе|✅ есть|❌ нет|
|Нужно ли переопределять в наследнике|❌ нет (по желанию)|✅ обязательно|
|Можно вызвать `base.Method()`|✅|❌ (нет реализации)|
|Можно пометить в `non-abstract` классе|✅|❌ (только в `abstract` классе)|

Пример:

`abstract class Animal {     public abstract void Speak();      // обязательно переопределить     public virtual void Eat() { }      // можно переопределить, можно нет }`

---

### 🔹 Модификатор `sealed` на override

Запрещает дальнейшее переопределение метода.

`class A {     public virtual void Foo() { } }  class B : A {     public sealed override void Foo() { } }  class C : B {     // public override void Foo() { } // ❌ нельзя — sealed }`

> Используется, если хочешь позволить переопределить метод **один раз**, но не дальше.

---

## 🔄 Вызов базовой реализации

`public override void SomeMethod() {     base.SomeMethod(); // вызывает метод базового класса     // своя логика }`

> `base` всегда указывает на реализацию базового класса, независимо от того, виртуальна она или нет.

---

## 💥 Полиморфизм (ключевой концепт)

Полиморфизм — это способность объектов **вести себя по-разному в зависимости от реального типа**, даже если они имеют общий интерфейс или базовый класс.

`List<Animal> animals = new() {     new Dog(),     new Cat() };  foreach (var a in animals)     a.Speak();`

> Вызываются разные реализации `Speak()` — **runtime polymorphism**.

## ⚠️ Важные детали, которые любят спрашивать

#### 1️⃣ Можно ли сделать конструктор виртуальным?

❌ Нет. Конструкторы не наследуются и не могут быть виртуальными.

---

### 2️⃣ Можно ли вызвать виртуальный метод в конструкторе?

✅ Можно, но это **опасно**:

- во время выполнения конструктора базового класса **объект ещё не полностью сконструирован** как наследник;
    
- вызов виртуального метода пойдёт в переопределение наследника, где поля ещё не инициализированы.
    

`class Base {     public Base() => Show();     public virtual void Show() => Console.WriteLine("Base.Show()"); }  class Derived : Base {     private string msg = "Derived";     public override void Show() => Console.WriteLine(msg); // msg == null! }`

Результат:

`(null)`

> 💡 Поэтому **не вызывай виртуальные методы из конструкторов.**

---

### 3️⃣ Можно ли сделать свойство виртуальным?

✅ Да:

`public virtual int Count { get; set; } public override int Count { get; set; }`

---

### 4️⃣ Можно ли переопределить статический метод?

❌ Нет. Статические методы **не могут быть виртуальными** и не участвуют в полиморфизме.  
Если в наследнике объявить такой же — это просто **скрытие (new)**.

---

### 5️⃣ Можно ли у `sealed class` делать виртуальные методы?

❌ Нет. `sealed` класс нельзя наследовать → виртуальные методы бессмысленны.

---

## 🧱 Типичная структура наследования

`abstract class Shape {     public abstract double GetArea();     public virtual void Draw() => Console.WriteLine("Drawing shape"); }  class Circle : Shape {     public double Radius { get; set; }     public override double GetArea() => Math.PI * Radius * Radius;     public override void Draw()     {         base.Draw();         Console.WriteLine("Drawing circle");     } }`

---

## 🧩 Связанные концепты

- **Polymorphism** — поведение метода определяется во время выполнения.
    
- **Encapsulation** — виртуальные методы позволяют менять реализацию, не меняя интерфейс.
    
- **Inheritance** — виртуальные методы — один из ключевых инструментов для расширения базовых классов.

## 🧠 Короткая шпаргалка для собеса (30 секунд)

> Виртуальный метод (`virtual`) — это метод, поведение которого можно изменить в наследнике с помощью `override`.  
> `abstract` — требует обязательного переопределения, `sealed override` — запрещает дальнейшее.  
> Если использовать `new`, метод **скрывается**, а не переопределяется — выбор метода зависит от типа ссылки.  
> Вызов виртуального метода определяется **в runtime** через виртуальную таблицу.  
> Полиморфизм — это когда один интерфейс даёт разные реализации в зависимости от реального типа объекта.
